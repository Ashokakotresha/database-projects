Running multiple users/Connections:

1. Start H2 Server mode

  java -jar h2-*.jar -tcp -web

This gives you:
TCP server → localhost:9092
Web console → http://localhost:8082
By default, this starts an H2 TCP server and opens the web console at http://localhost:8082.
Default credentials in the browser console are usually:

  User Name: sa
  Password: (leave blank)

1.1 Use the SAME JDBC URL everywhere  This is the most important rule:

jdbc:h2:tcp://localhost:9092/~/test

Do not mix with:
jdbc:h2:~/test   ❌ (embedded mode)

1.2 Create multiple “users” (connections)
You can simulate multiple users in different ways:

Option A — Browser sessions
Open 2 tabs (or incognito + normal)
Go to http://localhost:8082
Connect both using the TCP URL

Option B — Console + CLI
User 1 → Web console
User 2 → Shell:
java -cp h2-*.jar org.h2.tools.Shell

1.3 Option C — App + console
Your app (e.g., Spring Boot)
Plus H2 console


2. Run SQL commands in terminal: Once connected, you can create tables and insert data:
  Ctrl+D or type exit; to leave the shell.

  CREATE TABLE students (
      id INT AUTO_INCREMENT PRIMARY KEY,
      name VARCHAR(50),
      age INT
  );

  INSERT INTO students(name, age) VALUES('Alice', 22);
  INSERT INTO students(name, age) VALUES('Bob', 25);

  SELECT * FROM students;

1.4 Verify they are truly separate sessions

In User 1:
SET AUTOCOMMIT OFF;
UPDATE account SET balance = balance + 10 WHERE id = 1;

In User 2:
SELECT * FROM account WHERE id = 1;

You should not see the change yet → confirms proper isolation.

3. Connecting from Java

  import java.sql.*;

  public class H2Example {
      public static void main(String[] args) throws Exception {
          Connection conn = DriverManager.getConnection(
              "jdbc:h2:~/learning_db", "sa", ""
          );
          Statement stmt = conn.createStatement();
          stmt.execute("CREATE TABLE IF NOT EXISTS test(id INT PRIMARY KEY, name VARCHAR(100));");
          stmt.execute("INSERT INTO test VALUES(1, 'Ashoka');");
          ResultSet rs = stmt.executeQuery("SELECT * FROM test;");
          while(rs.next()){
              System.out.println(rs.getInt(1) + " " + rs.getString(2));
          }
          conn.close();
      }
  }

6 Use H2 Console for quick queries

  Open the browser at http://localhost:8082
  Connect with the same JDBC URL (jdbc:h2:~/learning_db) and credentials.
  You can run queries visually, which is great for learning.

 
=======================================================================================


If you started H2 server mode and also opened a shell with the file path (jdbc:h2:~/<database-name>).
The shell opened the database in embedded mode → exclusive file lock.
When you try to connect with browser to the same database (jdbc:h2:~/<database-name>), it gets “database already in use”.
Key point: You cannot mix embedded mode and server mode on the same database file.

Solution:  Always use the TCP URL when connecting through the server:

1. Launch H2 server (tcp + web) → Terminal 1
2. Open H2 shell with TCP URL → Terminal 2
3. Open browser console with TCP URL
4. Connect Java program with same TCP URL

------------------------------------------------------------------------------------

In H2 Database, the JDBC URL encodes both:
Access mode (embedded vs TCP)
Database identity (which DB instance/file)

If either differs → you are not sharing the same database session.

# H2 JDBC URL – Multi-User Connection Summary

## 1. Start H2 in Server Mode
Run H2 as a shared database server:

```bash
java -jar h2-*.jar -tcp -web
TCP Server: localhost:9092
Web Console: http://localhost:8082
```
## 2. Use the SAME JDBC URL Everywhere
All clients must use:
jdbc:h2:tcp://localhost:9092/~/sync-test

❌ Do NOT use:
jdbc:h2:~/sync-test

## 3. Understand the JDBC URL Structure
jdbc:h2:<MODE>://<HOST>/<DATABASE>
Part	Meaning
MODE	tcp, mem, or embedded
HOST	Server location
DATABASE	Database name/path

## 4. Ensure All Clients Match Exactly

For shared access, these must be identical:

Mode (tcp)
Host (localhost:9092)
Database path (~/sync-test)

## 5. Create Multiple Connections (Users)

You can simulate multiple users via:
Web Console (multiple browser sessions)

CLI Shell:
java -cp h2-*.jar org.h2.tools.Shell
Application (e.g., Spring Boot)

## 6. Verify Separate Sessions
In User 1:
SET AUTOCOMMIT OFF;
UPDATE account SET balance = balance + 10 WHERE id = 1;

In User 2:
SELECT * FROM account WHERE id = 1;

✔ If changes are not visible → sessions are independent

## 7. Common Mistakes to Avoid
Mixing embedded + TCP URLs
Using different DB paths (~/test vs ./test)
Using in-memory DB unintentionally
Leaving AUTOCOMMIT ON
Testing in only one session

## 8. Key Rule
The JDBC URL defines whether connections share the same database.
If the URL differs → you are NOT testing real multi-user behavior in H2 Database.
